# 週末ラボ

新しく出た技術を使って、**週末のあいだに作れるサイズ**のものを作る。1本 = 1フォルダ。

案は毎朝クラウドのルーチンが3つ送ってきます。見るのは https://sakidori.app/admin/lab

## 一覧

| # | 名前 | 何をするもの | 使った技術 | 状態 |
| --- | --- | --- | --- | --- |
| 001 | [form-agent](001-form-agent/) | 面倒なWebフォームを、保存した情報からAIが下書きする（送信は人） | Claude ブラウザ使用ツール `browser_toolset_20260801` | 実装完了・動作確認待ち |

## 状態の書き方

決まった言葉だけを使う。曖昧に書くと、あとで何が残っているか分からなくなる。

| 状態 | 意味 |
| --- | --- |
| 設計中 | まだコードが無い |
| 実装中 | 動くところまで行っていない |
| 動作確認待ち | 書き終えたが、まだ自分で通していない |
| 公開済み | 紹介ページと記事が出ている |
| 申請中 | ストアの審査待ち |
| 取りやめ | やめた。**消さずに理由を README に書く** |

## 1本ぶんのフォルダの作り方

```
lab/NNN-slug/
├── README.md        これは何か・いまどうなっているか・リンク（必須）
├── notes.md         設計メモ、詰まったこと（任意）
├── extension/       出て行くもの。種類をそのまま名前にする（web / worker / script）
└── _local/          録画・スクショ。git には入れない
```

番号は作った順。**やめたものも番号を空けずに残す**——何をやって何をやめたかが、後から効いてきます。

## 1本ぶんの出口（作ったら、この4つを出す）

| 出すもの | どこへ | 中身 |
| --- | --- | --- |
| 動くもの | ストア / sakidori.app / GitHub | 本体 |
| 紹介ページ | `sakidori.app/lab/<slug>` | 機能の概要と使い方（`POST /api/lab/build`） |
| 技術記事 | Zenn | 作る過程・詰まったところ |
| X の投稿2本 | X | ①作る過程（技術）②機能と使い方 |

技術的な話は **X と Zenn**、機能と使い方は **X と紹介ページ**、という分担です。
